# Getting CleanCut on the Chrome Web Store

The extension builds and packages. What's left is mostly paperwork and verifying the sites you want to claim.
There is no server to run: community data is the `catalog/` folder, read from GitHub, and the website is `site/` on GitHub Pages.

## 3. The manifest, and what slows review

`npm run package` drops `localhost`/`127.0.0.1`. What remains, in order of review risk:

1. **`optional_host_permissions: https://*/*, http://*/*`.** This is the biggest flag. It exists so Options can point at a custom catalog address and so
   CleanCut can run on any page with a video. Reviewers often put wildcard hosts in the slow "in-depth review" queue (days to weeks).
   Options: remove it from the store build (then the custom-catalog setting and arbitrary-page mode need `activeTab`-only behaviour,
   and `options.js` needs a guard around `chrome.permissions.request`), or keep it and justify it (section 5). Your call: it's a feature trade-off.
2. **Host access to 15 services** (55 match patterns in the current build). Each pattern must be justified. Launching with a
   smaller set (for example Netflix, Prime Video, YouTube, Vimeo) means a shorter justification, faster review and fewer unverified claims. Add services in later updates as you verify them.
3. **`https://raw.githubusercontent.com/*`** for the catalog. raw.githubusercontent.com answers cross-origin requests, so this permission may not be needed at all:
   try removing it and check the catalog still loads (untested). If it stays, note that Chrome ignores paths in host permissions, so it covers all of raw.githubusercontent.com.
4. **Content scripts are registered by the background worker** (not declared in the manifest), so reviewers read the permission list, not the script list. Say so in the justification.
5. Name: **"CleanCut — watch at your rating"** is fine. Keep service names out of the name and icon; mentioning them in the description to say where it works is allowed. Keep the "not affiliated" line.

Check the output: `npm run package && unzip -p extension/dist/cleancut-chrome.zip manifest.json`.

## 4. Listing copy (paste-ready)

**Summary (≤132 chars):**
> Watch any show at the rating you choose. Skips, mutes or hides scenes above your rating using a reviewed community catalog and subtitle scanning.

**Category:** Entertainment (alternative: Productivity)

**Description:**
> CleanCut lets you watch at the rating you choose. Pick R, PG-13, PG or G (or set each category yourself) and CleanCut skips, mutes or hides the picture of scenes above it while you watch, so the whole family can enjoy the same show.
>
> HOW IT WORKS
> • Community catalog: people flag scenes by category and severity; every tag is checked by a bot and reviewed by a person on GitHub before it's published.
> • Scan-ahead: when the player loads the episode's English subtitles, CleanCut analyzes them in your browser for profanity and revealing sound cues, before those scenes play. Optional Listen ahead does the same from the audio on sites that don't encrypt it, entirely on your computer.
> • Your own flags: click Flag scene on the player (or Alt+[ and Alt+]) to mark a scene as you watch, and share it with one click.
> • Undo any cut with one click. Share your settings as a skip list.
>
> PRIVATE BY DESIGN
> Subtitles and audio are analyzed on your device and never uploaded. No accounts, no CleanCut server, no ads, no tracking, no remote code. The extension reads public catalog files from GitHub and, only if you opt in to Listen ahead, downloads a speech model once.
>
> LIMITS
> CleanCut can't see the video picture (streaming video is protected), so it relies on the catalog and subtitles and can miss untagged scenes. Streaming sites change often; if something breaks, tell us on the support page. Beta: [LIST ONLY THE SERVICES YOU HAVE VERIFIED].
>
> CleanCut is independent and is not affiliated with or endorsed by any streaming service.

## 5. "Privacy practices" tab answers

**Single purpose:**
> Filter explicit scenes in the video the user is watching (skip, mute or hide them) according to the content rating the user chooses.

**Permission justifications:**

| Permission | Justification |
| --- | --- |
| Host access: the listed streaming sites | Needed to read which title is playing and its subtitle track, and to skip, mute or hide the picture of the player on those pages. |
| Host access: raw.githubusercontent.com | Reads the public community catalog (scene tags and skip lists) from the project's GitHub repository. |
| `storage` | Saves the user's rating, per-category settings, personal flags, timing adjustments and a short catalog cache. |
| `scripting` | The background worker registers and injects the content script so each part can be turned off from Options. |
| `activeTab` | Lets the popup read and control the player in the tab the user is looking at, and run on pages outside the listed sites when the user asks. |
| Optional access to all sites (if kept) | Requested only when the user chooses a custom catalog address or turns CleanCut on for another page; never required. |
| Page-world script | Netflix's player only allows seeking through its own page-world API (setting `currentTime` crashes it), and the players' subtitle/metadata requests are visible only there. With *Listen ahead* on for a site, it also passes a copy of the audio the player buffers to the extension, so profanity can be muted in videos without captions. |
| `offscreen` | Only when the user turns on *Listen ahead*: an offscreen document (reason `WORKERS`) runs the speech recognition model in workers, so it never runs on the video's page. It is closed when no tab is listening. |
| CSP `'wasm-unsafe-eval'` (extension pages) | onnxruntime-web, bundled in the package, compiles its WebAssembly to run the speech model. No code is fetched. |

**Remote code:** *No.* All code is bundled by esbuild into the package, the WebAssembly runtime included. *Listen ahead* downloads a model file (weights, data, not code) from Hugging Face, once, after the user agrees, checked against pinned checksums.

**Data usage disclosures.** Check against the form's current wording. CleanCut receives nothing: no server, no account. The extension reads files from GitHub, and requesting a
title's file reveals that title to GitHub (the host), and the opt-in speech-model download reveals the viewer's IP address (not what they watch) to Hugging Face. The privacy policy states both. If the form's definition of "collect" includes data that reaches a third-party host, tick
**Web history**; if unsure, over-disclosing is safer. Nothing else is handled.

**Certifications (tick all three):** data isn't sold; isn't used for unrelated purposes; isn't used for creditworthiness or lending.

## 6. Submit and what to expect

1. Dashboard → New item → upload the zip → fill the Store listing, Privacy and Distribution tabs.
2. Distribution: **Unlisted** is a good soft launch (link only, test the install flow with friends), switchable to Public later.
3. Typical review is a few days; wide host permissions or page-world scripts can take **1–3 weeks**. You can stage the release ("deferred publish").
4. Common rejections for this type of extension: *Excessive permissions*, *unclear single purpose*, *missing privacy policy details*, *intellectual property* (service names).

## 7. Risks to be honest about

- **Platform risk.** Services change their sites and could object. Comparable tools exist (ClearPlay, VidAngel, many Netflix-enhancement extensions), but there's no guarantee. The legal footing in the README (Family Movie Act) is US-only and isn't legal advice. Consider a short lawyer consult before a broad public launch.
- **It breaks silently.** If a service changes its player, skips can fail while mute/hide keeps working. Users see "doesn't work" reviews.
- **Fifteen services multiply that risk.** Each unverified adapter is a place a user can hit a bug. Verified-only listing copy keeps the promise honest.
- **Cold start.** The catalog holds one demo show. Until it fills, the value is the subtitle scan and users' own flags. Seed popular titles (or use `cleancut-scan`) before announcing.
